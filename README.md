# @dss/ui — 사내 시스템이 함께 쓰는 화면 조각

들어 있는 것이 둘이다 — **서비스 오가기 메뉴바**(1~6절)와 **알림 종**(7절).

직원은 하루에도 A/S · 계측기 · 개선요청을 여러 번 옮겨 다니는데, 지금은 그때마다
포털(`/apps`)로 돌아갔다 와야 한다. 메뉴바가 각 사이트 머리말에 앉아 한 번에
건너뛰게 한다. 사이트가 다섯이 될 예정이라 같은 코드를 다섯 벌 두지 않으려고
묶음으로 뺐다.

앉는 법이 둘이다(3절): 머리말 **위**에 가로로 늘어선 띠(`variant="bar"`, 기본)와,
머리말 **안**에 앉는 **드롭다운 단추**(`variant="inline"`). 지금 세 사이트는 모두
뒤쪽을 쓴다.

**알림 종**은 같은 머리말의 옆자리다. 종은 지금까지 A/S 에만 있었는데, 어느
시스템에 있든 종 하나로 **모든 시스템의 알림**을 보게 하려고 이리로 옮겼다 —
7절.


🔴 **두 조각은 서로를 부르지 않는다.** 하는 일이 비슷한 부분이 있어도(바깥을
눌러 접기) 폴더 하나가 제 것만 갖는다 — 메뉴바는 이미 세 사이트가 싣고 있어서,
새 조각을 위해 그 안을 넓히면 세 사이트가 함께 흔들린다. 종 폴더의
`no-network.test.ts` 가 `../` 로 시작하는 import 를 아예 막아 그 선을 지킨다.

---

## 1. 이 묶음이 하지 않는 것

🔴 **자료를 가져오지 않는다.** fetch 도, 포털 주소도, 로그인도, DB 도 모른다.
받은 목록을 그리기만 한다.

그래야

- 사이트마다 제 방식으로 목록을 구해 넣을 수 있고(세션에서든 토큰에서든),
- 이 묶음이 어느 사이트의 인증 방식에도 묶이지 않고,
- 시험이 브라우저도 서버도 DB 도 없이 돈다.

`no-network.test.ts` 가 소스를 읽어 **실제로 그런지** 못 박는다 — 바깥 모듈
호출, `fetch(`·`XMLHttpRequest` 같은 이름, 박힌 주소, `process.env` 를 전부
찾아 막는다. 조각마다 한 벌씩 있고(메뉴바 쪽은 `src` 아래 전부를 훑는다),
**새 파일이 늘어도 자동으로 걸린다.**

🔴 **권한을 판정하지 않는다.** 목록에 없는 것을 더하지 않고, 누가 어디에 들어갈
수 있는지 따지지 않는다. 그건 포털만 아는 것이고(`dss-auth` 의
`listAccessibleClients`), 판정이 두 벌이 되면 포털 타일과 메뉴바가 서로 다른
말을 하게 된다.

## 2. 받는 자료 — 포털이 토큰에 싣는 모양 그대로

```ts
type ServiceMenuEntry = {
  id: string;     // 포털의 clients.client_id
  name: string;   // 포털 타일(/apps)에 뜨는 것과 같은 이름
  url: string;    // {lan} 까지 펼쳐진 완성된 주소
  icon?: string;  // 이모지. 없으면 **키 자체가 없다**
};
```

원본은 `dss-auth/src/lib/oidc/service-menu.ts` 의 `ServiceMenuEntry` 이고,
포털이 로그인 ID 토큰의 **`dss_services`** 클레임에 싣는 한 칸의 모양이다.
이름·선택성(`icon` 만 `?`)을 **글자 하나까지** 맞춰 두었다. 사이트는 토큰에서
꺼낸 배열을 옮겨 담지 않고 그대로 넘기면 된다 — 옮겨 담는 코드가 생기는 순간
그것이 다섯 벌이 되고, 이 묶음을 만든 이유가 사라진다.

저장소가 서로 독립이라 그 타입을 `import` 할 수는 없어 베껴 적었다. 저쪽이 칸을
**늘리면** 여기는 그대로 두어도 되고(구조적 타입이라 통과한다), 이름을 바꾸거나
칸을 **빼면** 사이트에서 컴파일이 깨진다. 그때 고칠 곳은 `types.ts` 하나다.

### 쓰는 법

```tsx
import { ServiceMenuBar, normalizeServiceMenu } from "@dss/ui";

// 토큰/세션에서 꺼낸 값(타입이 없는 값)이라면 한 번 거른다.
const services = normalizeServiceMenu(claims.dss_services);

<ServiceMenuBar services={services} currentServiceId={MY_CLIENT_ID} />;
```

| prop | 뜻 |
|---|---|
| `services` | 그릴 목록. **받은 차례 그대로** 그린다. 비면 아무것도 그리지 않는다 |
| `currentServiceId` | 이 사이트의 `client_id`(= ID 토큰의 `aud`). 그 칸이 눌린 상태가 되고, `"inline"` 에서는 **드롭다운 단추에 서는 얼굴**까지 이 값이 정한다 |
| `label` | 화면 낭독기가 읽을 이름(기본 "사내 시스템 바로가기"). 🔴 `"inline"` 에서 지금 있는 서비스를 **모를 때**는 이 글자가 그대로 단추에 서므로 눈에도 보인다 |
| `colorScheme` | `"host"`(기본) · `"light"` · `"dark"` · `"system"` — 4절 |
| `variant` | `"bar"`(기본, 머리말 **위** 가로 띠) · `"inline"`(머리말 **안** 드롭다운 단추) — 3절 |
| `className` | 사이트가 바깥 여백·위치를 보탤 때 |

🔴 **`"inline"` 에서는 `currentServiceId` 를 꼭 넘긴다.** 안 넘겨도 죽지는 않지만
단추에 `label` 이 서서 「지금 어느 시스템에 있는지」를 알리는 값이 사라진다.

`normalizeServiceMenu` 는 **모양만** 본다: `id`·`name`·`url` 이 빈 칸을 버리고,
링크로 그릴 수 없는 주소(`javascript:` · `data:` · `//host`)를 버리고, 너무 긴
아이콘은 아이콘만 버리고, 겹친 `id` 는 먼저 온 것만 남긴다. 차례는 손대지
않는다.

## 3. 어디에 앉히나 — 앉는 법이 **둘**이고, 고르는 것은 사이트다

`variant` prop 하나로 갈린다. 🔴 **기본값은 `"bar"`**(머리말 **위** 독립된 띠)
이고, `"inline"`(머리말 **안** 드롭다운 단추)이 선택지다. 이 묶음은 「어디에
앉았는지」를 스스로 알아내려 하지 않는다 — 머리말 구조는 사이트마다 다르고,
짐작하는 순간 틀리기 시작한다.

| | `variant="bar"` (기본) | `variant="inline"` |
|---|---|---|
| 앉는 자리 | 머리말 **위**, 독립된 띠 | 머리말 **안**, 제목과 같은 줄 |
| 모습 | 서비스가 **가로로 다 늘어선다** | **단추 하나.** 누르면 목록이 아래로 펼쳐진다 |
| 바탕 | 머리말보다 한 단 눌린 회색 + 아래 테두리 | 없다 — 머리말 위에 그대로 얹힌다(펼친 목록만 제 바탕을 갖고 뜬다) |
| 차지하는 폭 | 서비스 수에 **비례해 늘어난다** | 단추 하나 — 서비스가 셋이든 열이든 **그대로** |
| 지금 있는 서비스 | 머리말과 같은 색 칸으로 **떠 있다**(브라우저 탭 은유) | **단추에 선다**(아이콘 + 이름). 펼친 목록에서는 굵기 + 진한 글자색 + 2px 밑줄 |
| 폰(<768px) | 이름까지 다 보이고 띠 안에서 굴러간다 | **단추가 아이콘 하나로 줄어든다.** 펼친 목록의 이름은 폰에서도 그대로 보인다 |
| 사이트 머리말 | 한 줄도 고치지 않는다 | 머리말이 이 조각을 제 줄 안에 그려야 한다 |

### 🔴 펼치고 접는 데 자바스크립트가 필요 없다

`<details>` + `<summary>` 다. **브라우저가 스스로** 펼치고 접고, 안에 든 것은
여전히 평범한 `<a href>` 라 눌리면 그대로 나간다. `ServiceMenuBar` 자체에는
상태도 이벤트 핸들러도 없으므로 **서버 컴포넌트로 남는다**(`"use client"` 를
붙이지 않는다 — 붙이는 순간 클라이언트 조각으로만 쓸 수 있게 된다).

`<select onChange>` 로 만들지 않은 이유가 바로 그것이다. 그것은 스크립트가 붙어야만
움직이는데, 사내망에서는 스크립트가 늦게 붙는 일이 실제로 있다(개선요청 머리말이
로그아웃을 평범한 `<form>` 으로 두는 것과 같은 판단이다). `ServiceMenuBar.test.tsx`
가 `<script`·`onclick`·`<select`·`<button` 이 마크업에 하나도 없다는 것을 못 박는다.

### 그 위에 **얹은** 것 — 바깥을 눌러 접기 · Esc 로 접기

`<details>` 는 바깥을 눌러도 Esc 로도 접히지 않는다. 그 둘만 작은 조각 하나
(`DropdownDismiss`)가 **얹는다.** 🔴 **얹은 것이지 갈아치운 것이 아니다** —
그 조각은 **아무것도 그리지 않고**(`null`), 펼침·접힘은 여전히 브라우저가 한다.

| | 스크립트가 붙기 전(또는 아예 없을 때) | 붙은 뒤 |
|---|---|---|
| 단추를 눌러 펼치기·접기 | **된다**(브라우저가 한다) | 된다 |
| 목록의 링크로 나가기 | **된다**(평범한 `<a href>`) | 된다 |
| 목록이 제대로 보이기 | **된다**(CSS 뿐이다) | 된다 |
| 바깥을 눌러 접기 | 안 된다 | 된다 |
| Esc 로 접기 | 안 된다 | 된다 |

- `"use client"` 는 **그 조각 파일 하나에만** 붙는다. `ServiceMenuBar` 는 그대로
  서버 컴포넌트다(서버 컴포넌트가 클라이언트 조각을 그리는 것은 막히지 않는다).
- 아무것도 그리지 않으므로 마크업이 한 글자도 늘지 않는다 — 서버에서 그린 것과
  브라우저에서 그린 것이 같아 hydration 이 어긋나지 않고, 사이트 쪽 머리말
  마크업 시험도 그대로다.
- 마우스·**손가락**·펜을 한 번에 받으려고 `pointerdown` 을 듣는다. `click` 으로
  들으면 iOS 에서 빈 바탕을 누른 것이 문서까지 오지 않아 **폰에서만** 안 먹는다.
- 화면이 사라질 때 붙인 것을 **전부 떼어낸다**(`useEffect` 뒷정리).
- 🔴 **`variant="bar"` 에는 아무것도 얹지 않는다** — 거기에는 `<details>` 자체가
  없다.
- 목록 **안**을 누른 것은 바깥이 아니라 접히지 않는다(목록은 제 안에서 세로로
  굴러간다 — 굴리려고 짚은 손가락에 접히면 못 쓴다). 링크를 누르면 어차피 다른
  사이트로 나가면서 사라진다.

### 왜 드롭다운인가 — 가로로 늘어놓으니 폭이 모자랐다

처음 `"inline"` 은 머리말 **안에서도 칸을 가로로 늘어놓는** 모습이었다. 그런데
머리말 한 줄을 햄버거 · 제목 · 이 목록 · 알림종이 함께 나눠 써야 해서 폰에서
자리가 모자랐다. 이름을 감추고 아이콘만 보여도, 목록이 제 안에서 가로로 굴러가게
해도 모자랐다 — 그리고 **서비스가 늘수록 나빠지는** 구조였다(지금 셋, 다섯이 될
예정이다).

그래서 2026-09-18 사용자 결정으로 **단추 하나 + 펼치는 목록**이 되었다. 이제
머리말이 잡아먹는 폭은 서비스 수와 **무관하다.** 덤으로 폰에서 이름을 감추느라
있던 장치들(가로 굴리기, 칸마다의 첫 글자 대체)이 **단추 한 곳으로 모였다.**

🔴 **새로 붙이는 사이트가 기본으로 고를 것은 여전히 `"bar"` 다.** `"inline"` 은
그 머리말이 한 줄짜리 `flex` 이고 단추 하나를 끼울 자리가 있을 때 값이 있다.
아니면 위에 앉히는 편이 싸다.

| 사이트 | 어떻게 앉았나 | 목록을 구하는 곳 |
|---|---|---|
| RF_Service_System (A/S) | **머리말 안**(`variant="inline"`). `AppShell.tsx` 가 조각을 만들어 `TopBar` 의 `serviceMenu` prop 으로 내리고, `TopBar` 가 제목과 알림종 **사이**에 그린다 | `src/app/(app)/layout.tsx` 가 서버에서 풀어 AppShell prop 으로 내린다 |
| njlee (계측기) | **머리말 안**(`variant="inline"`). `src/app/(internal)/layout.tsx` 가 `<AppHeader serviceMenu={…}/>` 로 내린다 | 같은 layout 이 서버에서 |
| dss-improvements (개선요청) | **머리말 안**(`variant="inline"`). `src/app/(app)/layout.tsx` 가 `<AppHeader serviceMenu={…}/>` 로 내린다 | 같은 layout 이 서버에서 |
| dss-auth (포털) | **넣지 않는다** — 그 자체가 목록이다 | — |
| dss-home · synergy-attendance | 아직 안 봤다. 고객용 화면에는 사내 메뉴가 나가면 안 되므로 **넣을지부터** 정해야 한다 | — |

> ⚠️ 세 사이트는 `vendor/dss-ui` 서브모듈이 **드롭다운 이전 커밋**을 가리키고
> 있는 동안에는 예전 모습(가로로 늘어선 줄) 그대로다. 포인터를 올리는 것은 별도
> 조각이고, 그때 각 사이트의 머리말 주석·시험 문구도 함께 손봐야 한다
> (「폰에서는 칸마다 아이콘만 보인다」 같은 설명이 이제 단추 이야기다).

### 붙일 때 챙길 것

- **스타일시트 한 줄.** 사이트 최상위 `layout.tsx`(또는 `globals.css` 를 부르는
  곳)에서 `import "@dss/ui/styles.css";` 를 한 번 한다. 이 조각은 CSS 를 스스로
  부르지 않는다 — 그러면 번들러 없이는 부를 수 없게 되어 시험이 깨진다.
- 🔴 **노치 인셋은 맨 위 요소 하나만 갖는다**(`viewport-fit=cover` 인 사이트).
  띠를 머리말 **위**에 앉혔다면 맨 위는 띠이므로
  `.dss-menu { --dss-menu-inset-top: env(safe-area-inset-top); }` 를 켜고 사이트
  머리말에서는 뺀다. 머리말 **안**으로 들였다면 맨 위는 다시 머리말이므로
  **머리말이 갖고**, 띠는 아무것도 하지 않는다(`inline` 모습은 그 패딩을 0 으로
  못 박아 둔다). 둘 다 두면 아이폰에서 노치 높이만큼 두 번 밀린다.
  A/S 는 지금 **머리말이 갖는다**.
- 🔴 **펼친 목록은 머리말 밖으로 나온다.** 단추 아래로 **떠서**(`position:
  absolute`) 그려지므로, 그것을 감싸는 머리말이나 그 조상에 `overflow: hidden`
  이 걸려 있으면 목록이 잘린다. 붙일 때 그 한 줄이 있는지 본다.
- **놓이는 방식이 모습마다 다르다.** `"bar"` 는 세로 `flex` 안에서 눌리지 않게
  `className="shrink-0"`. `"inline"` 은 이제 **단추 하나 폭**이라 예전처럼
  `min-w-0 flex-1` 로 남는 자리를 다 내줄 필요가 없다 — 그렇게 두어도 해롭지는
  않지만(단추는 왼쪽에 붙는다), 머리말을 손볼 때 `shrink-0` 쪽이 뜻이 더 맞다.
- **클라이언트 조각이 하나 딸려 온다**(`DropdownDismiss` — 바깥을 눌러 접기 ·
  Esc). 서브모듈로 가져다 쓰면 Next 가 제 앱 코드처럼 컴파일하므로 할 일이
  없다(5절 5번). 사이트가 `ServiceMenuBar` 를 **서버 컴포넌트에서** 그리든
  `"use client"` 껍데기 안에서 그리든 둘 다 그대로 된다 — 그 조각은 prop 을
  하나도 받지 않아 서버→클라이언트로 넘길 값 자체가 없다.
- **인쇄.** CSS 가 `@media print` 로 스스로 감춘다. 사이트 쪽 `print:hidden` 을
  또 걸 필요 없다(걸어도 해롭지 않다).
- **로그인 전 화면에는 넣지 않는다.** 목록이 없으면 어차피 아무것도 안 그리지만,
  로그인 화면 위에 자리만 생기지 않게 보호 구간 layout 안에 둔다.

## 4. 다크 모드

사이트마다 다크를 켜는 방식이 다르다. 실제로 이렇다:

- `RF_Service_System` : `@custom-variant dark (&:where(.dark, .dark *))` — **클래스**로 켠다.
  `ThemeToggle.tsx` 가 `document.documentElement.classList.toggle("dark", …)` 로
  `<html>` 에 건다(「시스템 설정 따름」도 JS 에서 계산해 결국 이 클래스가 된다).
  그래서 A/S 에서는 `colorScheme` 을 건드릴 필요가 없다 — 기본값이 맞다.
- `njlee` : 다크 변형이 없고 `color-scheme: light` 로 **라이트 고정**이다.

그래서 이 묶음은 Tailwind 의 `dark:` 유틸리티를 **쓰지 않는다.** 썼다면 Tailwind
기본값인 `prefers-color-scheme` 이 적용되어, 계측기에서 OS 가 어두운 사람에게만
**이 띠 하나만** 까맣게 뜬다. (게다가 Tailwind v4 는 `node_modules` 안을 훑지
않으므로 유틸리티로 짜면 사이트마다 `@source` 한 줄을 또 넣어야 한다. 어차피 한
줄 넣을 거라면 그 한 줄이 CSS import 인 편이 낫다 — 번들러도 프레임워크도 안 탄다.)

대신 색을 전부 CSS 변수로 두고 **네 가지 신호**를 받는다:

| `colorScheme` | 어두워지는 조건 |
|---|---|
| `"host"` (기본) | 조상에 `.dark` 또는 `[data-theme="dark"]` 가 있을 때 |
| `"dark"` / `"light"` | 사이트가 어떻든 이 띠만 고정 |
| `"system"` | OS 설정(`prefers-color-scheme`) |

기본값이 `"host"` 라서 A/S(클래스 방식)와 계측기(라이트 고정)가 **둘 다 그대로
옳게** 나온다. 사이트가 제 색으로 맞추고 싶으면 변수만 덮으면 된다:

```css
.dss-menu {
  --dss-menu-bg: #f8fafc;
  --dss-menu-accent: #0f172a;
}
```

펼친 목록(드롭다운)의 색도 같은 방식이다 — `--dss-menu-panel-bg` 와
`--dss-menu-panel-shadow` 두 개가 따로 있다. 목록은 본문 **위에 떠서** 그려지므로
제 바탕이 있어야 아래 글자가 비치지 않는다.

라이트에 있는 색은 다크에도 **전부** 있어야 한다(한쪽만 빠지면 그 색만 반대 모드
값을 물려받아 글자가 바탕에 묻는다). `service-menu.css.test.ts` 가 네 블록
(라이트 · 다크 · `system` 다크 · 라이트 고정)을 맞대 대조한다.

## 5. 🔴 사이트가 이 묶음을 어떻게 가져다 쓰나 — 정해야 할 것

저장소 다섯이 각자 독립이고 도커로 따로 빌드한다. **지금은 저장소끼리 코드를
공유하는 구조가 아예 없다.** 그래서 묶음을 만든 것만으로는 부족하고, 사이트가
이것을 어떻게 받아 오는지를 정해야 한다.

각 사이트의 Dockerfile 은 `COPY . .` — **빌드 맥락이 그 저장소 폴더 하나**다.
옆 폴더(`../dss-ui`)는 이미지 안으로 들어가지 않는다. 이 한 줄이 아래 선택지의
값을 거의 다 결정한다.

### 길 비교

| | 새로 만들 것 | 도커 빌드 변화 | 코드 벌 수 | 값(비용) |
|---|---|---|---|---|
| **ㄱ. 소스 복사 + 맞춤 스크립트** | 복사 스크립트 하나, 각 사이트에 `src/components/dss-ui/`, 드리프트 검사 시험 | 없음 | **다섯 벌** | 가장 단순하지만 **복사본이 다섯 벌 남는다** — 이번에 안 하기로 한 바로 그것 |
| **ㄴ. git submodule** ⭐ | `dss-ui` 를 저장소로 만들고 원격에 올린다. 각 사이트에 `.gitmodules` + `vendor/dss-ui`, `tsconfig.paths` 별칭 한 줄, eslint 무시 한 줄 | **없음** — 체크아웃되어 있으면 `COPY . .` 가 같이 담는다 | **한 벌** | 서브모듈 의식: 클론할 때 `--recurse-submodules`, 묶음을 먼저 올리고 사이트의 포인터 커밋을 따로 올려야 한다 |
| **ㄷ. npm 꾸러미 파일(tgz) 고정** | `npm pack` 산출물을 각 사이트 `vendor/` 에 두고 `"@dss/ui": "file:vendor/…tgz"`, `next.config` 에 `transpilePackages` | 없음(꾸러미가 맥락 안에 있어 `npm ci` 가 오프라인으로 깐다) | 한 벌 + 꾸러미 다섯 | 고칠 때마다 pack → 다섯 곳에 **바이너리 파일 교체 커밋**. 무엇이 바뀌었는지 diff 로 안 보인다 |
| **ㄹ. 사내 npm 레지스트리(NAS)** | NAS 에 레지스트리 서비스(Verdaccio 등) + 계정 + 백업 대상 하나 + 사이트마다 `.npmrc` | 빌드가 레지스트리에 **닿아야** 한다 | 한 벌 | 가장 '제대로'지만 **운영할 서비스가 하나 는다.** 그것이 죽으면 다섯 사이트의 빌드가 함께 멈춘다 |
| **ㅁ. 모노레포로 합치기** | 다섯 저장소 통합, 배포 파이프라인 전면 재작성 | 전면 | 한 벌 | 지금 할 일이 아니다 |

### 추천: **ㄴ. git submodule**

이유:

1. **코드가 한 벌이다.** 이번 결정("복사본 다섯 벌은 안 둔다")을 실제로 지키는
   길은 ㄴ·ㄷ·ㄹ 셋뿐이다.
2. **도커가 안 바뀐다.** 서브모듈은 저장소 폴더 **안**에 체크아웃되므로
   `COPY . .` 가 이미 담아 간다. Dockerfile 도, `npm ci` 도, `.dockerignore` 도
   손대지 않는다.
3. **운영할 것이 늘지 않는다.** NAS 에 새 서비스를 띄우지 않는다(ㄹ 과의 차이).
   사내망이 끊겨도 빌드된다.
4. **사이트마다 언제 따라갈지 고른다.** 서브모듈은 커밋 SHA 로 고정된다. 띠를
   고쳐도 A/S 만 먼저 올려 보고, 나머지 넷은 다음 배포 때 따라가면 된다 —
   다섯이 한꺼번에 흔들리지 않는다. 이 회사처럼 사이트마다 배포 주기가 다른
   곳에서는 이게 가장 큰 값이다.
5. **번들러 설정이 필요 없다.** 저장소 안의 소스라 Next 가 제 앱 코드처럼
   컴파일한다 — `transpilePackages` 도, Tailwind `@source` 도 필요 없다
   (ㄷ 과의 차이).

맞바꾸는 것(솔직히):

- 서브모듈은 익히기 전에는 헷갈린다. **묶음을 먼저 올리고, 그 다음에 사이트의
  포인터 커밋을 올린다** — 순서를 바꾸면 남의 컴퓨터에서 체크아웃이 안 된다.
- 새로 클론할 때 `git clone --recurse-submodules` 를 잊으면 `vendor/dss-ui` 가
  빈 폴더가 된다. 그때는 **빌드가 크게 실패한다**(조용히 옛 코드가 쓰이지는
  않는다) — 헷갈리지만 위험하지는 않은 실패다.
- 이 길을 고르려면 먼저 `dss-ui` 를 git 저장소로 만들고 원격에 올려야 한다.
  **이번 조각에서는 하지 않았다**(지시에 따라 `git init` 하지 않았다).

**ㄷ(tgz) 는 좋은 차선이다.** 서브모듈 의식이 실제로 성가시게 굴면 갈아타면
된다 — 고쳐야 할 것은 각 사이트의 `package.json` 한 줄과 `next.config` 한 줄뿐,
이 묶음의 코드는 그대로다. **ㄹ(사내 레지스트리)** 은 공유 조각이 여럿이 되고
사이트마다 다른 판을 써야 할 때 가는 곳이지, 조각 하나에 서비스를 하나 띄울
일은 아니다.

> 어느 길이든 **이번 조각에서는 실행하지 않았다.** 사이트에 붙이는 것은 다음
> 조각이고, 그때 사람이 위에서 고른다.

## 6. 시험

```bash
npm install
npx tsc --noEmit
npm run lint
npm test
```

`npm test` 는 `node --test` 로 돈다(새 시험 라이브러리를 들이지 않았다 — 사이트
저장소들과 같은 방식이다). 브라우저도 jsdom 도 쓰지 않고 `react-dom/server` 로
**진짜로 그려** 나온 마크업을 확인한다.

시험이 못 박는 것(**메뉴바**. 종이 못 박는 것은 7절 끝에 따로 적었다):

- 목록이 비어도(권한이 없거나 아직 못 받았거나) 죽지 않고 **빈 띠도 남기지 않는다**
- 지금 있는 서비스 **한 칸만** 눌린 상태가 된다 — 모르는 id 를 넘겨도 죽지 않는다
- **받은 차례 그대로** 그린다
- 🔴 **망을 타지 않는다** — 바깥 모듈도, 박힌 주소도, 환경변수도 없다
- 다크에 라이트의 색이 하나도 빠지지 않았다
- 마크업이 쓰는 클래스에 규칙이 다 있다(그 반대도)
- 서비스가 열로 늘어도 그려지고, 좁은 화면에서는 띠 안에서만 굴러간다
- 🔴 **기본 모습이 예전 그대로다** — `variant` 를 안 넘긴 것과 `"bar"` 가 글자
  하나까지 같고, 거기에는 `<details>` 도 `<summary>` 도 섞이지 않는다
- 🔴 **자바스크립트 없이 펼쳐진다** — 새 모습은 같은 `<ul>` 을 `<details>` 로
  감쌀 뿐이고(목록 자체는 두 모습이 **글자 하나까지 같다**), 마크업에
  `<script`·`onclick`·`<select`·`<button` 이 하나도 없다. 칸은 여전히 평범한
  `<a href>` 다
- 🔴 **단추에 지금 있는 서비스가 선다** — 모르면 `label` 이 서서 빈 단추가 되지
  않고, 펼친 목록에서는 그 칸이 `aria-current="page"` 로 표시된다
- 🔴 새 모습이 **바탕과 아래 테두리를 갖지 않는다**(펼친 목록만 제 바탕을 갖고
  **떠서** 그려진다), 빈 목록이면 둘 다 아무것도 그리지 않는다
- 🔴 폰에서 **단추의** 이름을 **눈에서만** 감춘다(낭독기는 그대로 읽는다)는 것,
  펼친 목록의 이름은 폰에서도 보인다는 것, 그리고 아이콘이 없는 서비스에서
  단추가 🔗 하나로 끝나지 않는다(이름 첫 글자로 메운다)는 것
- 🔴 **바깥을 눌러 접기 · Esc 로 접기는 얹은 것이다** — 곁들인 조각이 마크업을
  한 글자도 늘리지 않고(`null` 을 돌려준다), 서버에서 그려도 터지지 않고,
  `pointerdown`(폰까지)과 `keydown` 을 붙였다가 **전부 떼어낸다**. 목록 **안**을
  누른 것은 접지 않는다

## 7. 알림 종(`NotificationBell`)

사내 시스템이 여럿인데(A/S · 포털 · 계측기 · 개선요청 · PO · 휴가) **종은 A/S
에만 있었다.** 어느 시스템에 있든 종 하나를 열면 모든 시스템의 알림이 보이게
만드는 중이고, 이 조각은 그 **그리는 쪽**이다.

지금까지 된 것: A/S 가 「이 사람의 알림」을 내주는 통로를 열었고, **포털이 각
시스템에 물어 합쳐 준다**(dss-auth 의 `lib/notifications/merge.ts` — 실제 왕복
확인됨). 이 조각은 그 **합친 목록을 받아 그리기만** 한다.

🔴 **자료를 가져오지 않는다**(1절). 포털 주소도, 로그인도, 다시 물어보는 주기도
모른다. 무엇을 넣을지는 사이트가 정한다.

### 받는 자료 — 포털이 합쳐 내주는 모양 그대로

```ts
type NotificationBellItem = {
  key: string;        // 목록 전체에서 유일. 포털에서는 `client_id:id`
  sourceId: string;   // 어느 시스템에서 왔는가(client_id)
  sourceName: string; // 그 시스템의 사람이 읽는 이름
  id: string;         // 그 시스템 안에서의 알림 id
  kind: string;       // 종류 코드. 🔴 이 묶음은 어느 시스템의 종류 목록도 모른다
  kindLabel: string;  // 사람이 읽는 종류 이름("결재 대기")
  subject: string;    // 굵게 오는 대상(인수번호 등)
  detail: string;     // 무슨 일인가
  href: string;       // 🔴 받은 그대로 나간다
};
```

원본은 `dss-auth/src/lib/notifications/merge.ts` 의 `PortalNotificationItem` 이고
**글자 하나까지** 맞춰 두었다(`types.ts` — 메뉴바가 `ServiceMenuEntry` 를 베껴
적은 것과 같은 자리·같은 이유). 🔴 **없는 값은 빈 문자열이다**(`?` 가 아니다) —
포털이 그렇게 싣는다.

### 쓰는 법

```tsx
import { NotificationBell } from "@dss/ui";
import "@dss/ui/notification-bell.css"; // 최상위 layout 에서 한 번

<NotificationBell
  items={feed.items}          // 포털에서 받은 배열을 **그대로**
  count={feed.count}          // 🔴 보낸 쪽이 센 값 그대로
  onAcknowledge={(item) => …} // 없어도 된다
/>;
```

| prop | 뜻 |
|---|---|
| `items` | 그릴 목록. **받은 차례 그대로** 그린다. 비면 **아무것도 그리지 않는다** |
| `count` | 배지에 찍을 숫자. 🔴 **받은 값 그대로** 찍는다(아래 「개수」). 0 이하·숫자가 아니면 배지만 없다 |
| `label` | 화면 낭독기가 읽을 이름(기본 "알림"). 눈에는 안 보인다 — 종은 아이콘 하나짜리 단추다 |
| `onAcknowledge` | 줄을 눌렀을 때 부른다. 「확인했다」를 적는 일은 **사이트가** 한다(아래 「확인」) |
| `colorScheme` | `"host"`(기본) · `"light"` · `"dark"` · `"system"` — 4절과 같은 뜻 |
| `className` | 사이트가 바깥 여백·위치를 보탤 때 |

### 🔴 옮기면서 내린 결정 넷

**1. 색 — 표가 아니라 셈으로 고른다.** A/S 의 종은 종류마다 글자색이 다른데, 그
색은 `text-amber-700 dark:text-amber-400` 같은 **Tailwind 클래스 이름**으로 적혀
있다. 그것을 그대로 옮겨 오면 색이 **조용히 사라진다** — Tailwind 는 자기
저장소 소스에서 글자로 찾은 클래스만 CSS 로 만들고 v4 는 `node_modules` 안을
훑지 않으므로, 묶음에서 건너간 클래스에는 규칙 자체가 없다. 오류도 나지 않는다.
포털도 같은 이유로 **색을 보내지 않기로** 했다(`kind` 와 `kindLabel` 만 싣는다).

그래서 색은 이 묶음이 제 CSS 로 입힌다. 종류 코드를 해시해 **색 칸 16 개 중
하나**를 집고(`tone.ts`), 마크업에는 `data-tone="5"` 만 실린다. 표를 두지
않은 이유: 표를 두면 시스템마다 다른 종류 목록이 묶음 안으로 들어와, 종류가 늘
때마다 이 저장소를 고치고 다섯 사이트가 그 판을 따라 올려야 한다.

- 같은 종류는 **어느 화면에서도, 새로고침해도 같은 색**이다(순수 함수).
- 맞바꾸는 것: 서로 다른 두 종류가 같은 칸에 앉을 수 있다. 그래도 정보는 남는다 —
  🔴 **종류 이름을 글자로도 함께** 그리기 때문이다(색약·흑백 인쇄 때문에 그
  규칙이 먼저다). 지금 도는 여덟 종류(A/S)는 서로 겹치지 않는다 — 시험이 확인한다.
- 색 값은 사이트들의 Tailwind v4 가 내놓는 것과 **같은 oklch 값**을 그대로 적었다
  (라이트는 `-700`, 다크는 `-400`). 같은 화면에 함께 뜨는 색이라 한 식구로 보여야 한다.

**2. 「확인했다」 — 부르기만 한다.** A/S 는 정보성 알림(승인 완료·반려됨)을 눌러
확인하면 서버에 적고 종에서 뺀다. 🔴 **묶음은 서버를 모른다.** 어디에 적을지는
물론, 애초에 **이 종류가 눌러 확인하는 종류인지조차** 여기서 정하지 않는다 —
그건 그 알림을 만든 시스템만 아는 것이다(A/S 는 도메인 판정 한 곳이 정한다).
그래서 줄을 누르면 `onAcknowledge(item)` 를 부르고 끝이다. 받은 사이트가 제
규칙으로 가려 적는다.

- 🔴 **이동은 이 함수와 무관하다.** 줄은 평범한 `<a href>` 라 브라우저가 나간다.
  `onAcknowledge` 가 **던져도 이동은 그대로 간다**(확인을 못 적으면 그 줄이 종에
  남을 뿐이다 — A/S 가 이미 같은 판단을 하고 있다).
- 눌린 줄을 어떻게 아나: 줄마다 `data-notification-key` 가 실려 있고, 곁들인
  조각이 그 값으로 `items` 에서 줄을 되찾아 통째로 넘긴다.
- 🔴 확인은 `pointerdown` 이 아니라 **`click`** 에 센다. 목록을 굴리려고 짚은
  손가락까지 「눌렀다」로 세면 읽지도 않은 알림이 사라진다.

**3. 클라이언트 경계 — 꼭 필요한 조각 하나만.** `NotificationBell` 자체는
**서버 컴포넌트다**(`"use client"` 가 없다). 펼치고 접는 일을 `<details>` +
`<summary>` 에 맡겼기 때문에 상태도 이벤트 핸들러도 없다 — 메뉴바의
`variant="inline"` 과 똑같은 선택이고, 얻는 것도 같다: 스크립트가 아직 안 붙은
화면에서도 종을 열어 읽고 링크로 나갈 수 있다(사내망에서는 실제로 늦게 붙는다).
덤이 하나 더 있다 — **정적 렌더 시험이 펼친 속까지 그대로 본다**(`useState` 로
여닫았다면 시험에서는 늘 닫힌 종만 보인다).

`"use client"` 는 `BellBehavior.tsx` **하나뿐**이고, 그 조각은 **아무것도 그리지
않는다**(`null`). 얹는 것은 셋 — 바깥을 눌러 접기 · Esc 로 접기 · 확인 알리기.
스크립트가 없으면 그 셋만 없고 나머지는 그대로다.

| | 스크립트가 붙기 전 | 붙은 뒤 |
|---|---|---|
| 종을 눌러 펼치기·접기 | **된다**(브라우저가 한다) | 된다 |
| 줄을 눌러 그 화면으로 가기 | **된다**(평범한 `<a href>`) | 된다 |
| 배지·목록이 제대로 보이기 | **된다**(CSS 뿐이다) | 된다 |
| 바깥을 눌러 접기 · Esc | 안 된다 | 된다 |
| 「확인했다」 적기 | 안 된다(줄이 종에 남는다) | 된다 |

**4. 다크 모드 — `dark:` 유틸리티를 쓰지 않는다.** 4절과 같은 이유이고 같은
방식이다: 색을 전부 `--dss-bell-*` 변수로 두고 네 신호(`host`(기본) · `dark` ·
`light` · `system`)를 받는다. 기본값이 `"host"` 라서 A/S(클래스 방식)와
계측기(라이트 고정)가 둘 다 그대로 옳게 나온다. 라이트에 있는 색은 다크에도
**전부** 있어야 하고(색 칸 16 개까지), `notification-bell.css.test.ts` 가 네
블록을 맞대 대조한다.

### 개수 — 🔴 다시 세지 않는다

배지의 숫자는 **받은 값 그대로**다. 세는 규칙이 시스템마다 다르기 때문이다 —
A/S 는 「같은 대상은 한 번만」 센다(한 건에 결재가 둘 걸려 있어도 1). 여기서 줄
수를 세면 각 시스템의 종과 이 종이 **서로 다른 숫자를 말하게 된다**. 포털이 각
시스템이 센 값을 더하기만 하는 것과 같은 선이다.

그래서 **참말을 넣어야 한다.** 줄 수와 달라도 묶음은 고쳐 주지 않는다.

### 붙일 때 챙길 것

- **스타일시트 한 줄.** `import "@dss/ui/notification-bell.css";` 🔴 메뉴바의
  `@dss/ui/styles.css` 와 **다른 파일**이다 — 쓰는 조각 것만 부르면 된다(묶어
  두려면 CSS 에서 `@import` 를 해야 하는데, 그것은 시험이 막는다).
- 🔴 **목록이 비면 종 자체가 없다.** 이것은 **A/S 의 지금 종과 다른 점**이다
  (그쪽은 빈 종도 그린다). 알림이 없는 것은 정상이고 그때 볼 것도 할 일도
  없으므로 머리말에 「눌러도 아무것도 없는 단추」를 남기지 않는다. 붙이는
  사이트가 이 차이를 알고 골라야 한다 — 늘 자리를 잡아 두고 싶으면 사이트가
  그 자리를 잡는다(빈 `<div className="w-9" />` 같은 것).
- 🔴 **펼친 목록은 머리말 밖으로 나온다.** 종 아래로 **떠서** 그려지므로,
  감싸는 머리말이나 그 조상에 `overflow: hidden` 이 걸려 있으면 잘린다.
- 🔴 **`onAcknowledge` 는 함수다.** 사이트의 **서버 컴포넌트**에서 이 종을
  그린다면 넘길 수 있는 것은 **서버 액션뿐이다**(평범한 함수는 클라이언트
  경계를 건너지 못한다 — React 가 대놓고 오류를 낸다). `"use client"` 껍데기
  안에서 그린다면 아무 함수나 된다(A/S 의 `AppShell` 이 그 경우다).
- **인쇄.** CSS 가 `@media print` 로 스스로 감춘다.
- **로그인 전 화면에는 넣지 않는다.**

### 🔴 다음 조각(각 사이트가 붙이기)이 할 일

1. **목록을 구해 온다.** 포털의 통로에 물어 `items`·`count` 를 얻는다 — 어디에
   물을지·얼마 만에 다시 물을지·세션을 어떻게 실을지는 **사이트가** 정한다.
   이 묶음은 받기만 한다.
2. **머리말에 앉힌다.** A/S 는 `TopBar` 의 지금 종을 이것으로 갈아 끼우고(그
   자리의 브라우저 알림창·시험 알림 단추를 어떻게 할지 함께 정해야 한다 — 그
   둘은 **이 묶음에 오지 않았다**), 나머지 사이트는 제 머리말에 새로 단다.
3. **`onAcknowledge` 를 잇는다.** A/S 는 지금 쓰는 서버 액션
   (`acknowledgeNotificationAction`)에 `item.id` 를 넘기면 되고, 포털을 거쳐 온
   줄이라면 `item.sourceId` 로 **어느 시스템에 적을지**부터 정해야 한다 — 포털에
   그 통로가 아직 없다.
4. **「눌러서 확인하는 종류인가」를 사이트가 가린다.** 묶음은 모든 줄에서
   `onAcknowledge` 를 부른다.
5. **못 물어본 시스템(`degraded`)을 어떻게 보일지 정한다.** 포털은
   `PortalNotificationFeed` 에 `sources`·`degraded` 를 함께 내주는데, 🔴 **이
   조각은 그 둘을 받지 않는다**(이번 조각은 「그리는 것」까지다). 「알림이
   없다」와 「못 물어봤다」는 다른 말이므로, 종이 그 둘을 같은 얼굴로 그리지
   않으려면 **prop 을 하나 더 열어야 한다.** 그때 이 README 와 시험도 함께 는다.
6. **받은 JSON 을 거를지 정한다.** 메뉴바에는 `normalizeServiceMenu` 가 있지만
   종에는 주소 검사(`isSafeNotificationHref`)뿐이다. 사이트마다 제 검사를 적기
   시작하면 그것이 다섯 벌이 되므로, 두 번째 사이트를 붙일 때쯤 묶음에
   `normalizeNotifications` 를 두는 편이 낫다.

### 종의 시험이 못 박는 것

- 🔴 **망을 타지 않는다** — 바깥 모듈도, 박힌 주소도, 환경변수도 없고,
  **옆 폴더(메뉴바)도 부르지 않는다**
- 🔴 목록이 비면 **아무것도 그리지 않는다** — 빈 종도, 배지도
- 🔴 배지는 **받은 값 그대로**다(줄이 셋인데 7 이라고 하면 7 로 찍는다)
- 🔴 링크는 **받은 그대로** 나간다(쿼리·앵커까지), `javascript:` 같은 주소는
  **그 줄만** 빠지고 글자로도 남지 않는다
- **받은 차례 그대로** 그린다
- 🔴 **자바스크립트 없이 펼쳐진다** — 마크업에 `<script`·`onclick`·`<button`·
  `<select` 가 하나도 없고, 줄은 평범한 `<a href>` 다
- 🔴 곁들인 조각이 **마크업을 한 글자도 늘리지 않고**(`null`), 서버에서 그려도
  터지지 않고, 세 사건을 붙였다가 **전부 떼어낸다**(같은 옵션으로)
- 🔴 확인 함수가 **던져도 밖으로 새지 않는다**(이동을 막으면 안 된다)
- 🔴 종류는 **색과 함께 글자로도** 그려지고, 색 칸은 `tone.ts` 의 수만큼 CSS 에
  다 있다(라이트·다크 네 벌 모두)
- 남의 시스템에서 온 글자는 **글자로만** 그려진다(마크업이 되지 않는다)
- 보낸 쪽이 안 실은 칸(종류·시스템 이름·상세)은 **빈 자리를 남기지 않는다**
